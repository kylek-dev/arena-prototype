# Frontend boundaries and behavior

## Public modules

- `bridge/snapshot.ts`: validated Rust-to-browser practice contract. Combat numbers come from Rust, never local preferences. `loader.ts` loads generated static assets relative to the document.
- `runtime/start.ts`: installs the bridge and event adapters once, outside React. `commands.ts` resolves slot IDs to today's sole real ability before submitting the existing attack intent. No ability IDs, damage or coordinates are accepted from preferences as authority.
- `runtime/input-router.ts`: conflict → capture → quick bind → modal/typing → layout → gameplay precedence. `runtime/focus.ts` returns focus from ordinary HUD controls without losing movement, but respects explicit keyboard owners, window focus and Shift+Tab navigation. Keyboard-owning mode transitions, window blur, hiding and unexpected lock loss clear holds. One-shot repeats are consumed without dispatch. Alternate physical holds are tracked separately.
- `domain/bindings`: action identities, primary/secondary entries, supported physical chords, conflicts and held resolution. UI labels use physical US-style codes, not the user's printed keyboard layout.
- `domain/action-bars`: stable IDs, bounded configuration, immutable atomic placement. Catalog placement copies; slot drag moves/swaps; Shift-drag copies. `runtime/spell-drag.ts` handles same-page payloads and canvas discard; dropping a slotted spell on the canvas clears the assignment but preserves slot/binding identity. Cancel/invalid/stale/catalog-to-canvas drops are no-ops. Spellbook assignment is deliberately drag-only per user request; no dropdown or keyboard placement/removal forms remain. Locks protect assignments, not click/key activation; drags suppress gameplay and trailing clicks.

  Placement now uses captured pointer gestures rather than native HTML drag events ([ADR 0009](decisions/0009-pointer-spell-placement.md)). The four-pixel threshold distinguishes click from drag; release coordinates select the destination independently of the captured event target. Armed presses defer canvas focus reclamation, actual drags clear gameplay intent, and trailing clicks cannot cast. A ghost icon and slot outline provide feedback. A locked profile exposes an explicit Unlock spell dragging control in the spellbook; no saved lock is silently overwritten. Base icons/tracks/previews are 64×64 CSS px through one shared token; configured scaling/viewport fitting still apply.
- `domain/layout`: offsets are fractions of available top-left travel after scaling, not raw pixels or viewport percentages. Placements have a 12px viewport margin, clamp offsets and fit oversized content. `ui/useMovable.ts` shares bounded movement between whole-frame drags and the movable editor title. Frame drag drafts persist only on release; selected frames also support arrows. Editor-window position is session-only. Layout lock is independent of assignment lock.
- `domain/units`: deterministic next-identity selection and identity-based focus reconciliation. Current bridge has exactly one opponent; multi-opponent cycling has not been demonstrated. Target/focus read the same latest entity state, not copied health. Reset and disappearance clear focus.
- `domain/preferences`: versioned validation, safe recovery, profiles and debounced persistence. Unknown future data is never silently overwritten. Import creates fresh profile IDs and unique names; up to eight profiles. Recovery overwrite requires explicit confirmation.
- `state`: small external stores expose immutable snapshots; selector results must be stable references or primitives, not newly allocated objects. Ordinary HUD snapshots are throttled to 80 ms, but cooldown starts/ends/increases and session resets deliver immediately. Rust still runs every tick. Preferences never persist engine snapshots.
- `ui`: reusable Radix dialog/tooltip wrappers and viewport placement, styled with Radix Themes 3.3.0. Modal dialogs trap/restore focus; the nonmodal spellbook retains gameplay focus and stays open during canvas interaction. Portals remain in the themed overlay. Feature editors are public composition entry points, not shared private subcomponents.

## Shared tooltips

`ui/Tooltip.tsx` owns the app-wide `TooltipProvider`, `Hint` trigger/portal behavior and optional `TooltipCard` layout. Use `Hint` with one native focusable element (or a component forwarding its ref and event props). Supply descriptive content, not interactive controls; use a dialog/popover for controls. Hover, keyboard focus, Escape dismissal and accessible descriptions use pinned Radix Tooltip 1.2.8. Provider defaults to a 300 ms hover delay and suppresses open/new tooltips during spell dragging, layout editing and binding capture/quick bind. Placement flips/shifts within a 12 px viewport margin; portals stay inside the themed overlay.

`TooltipCard` supplies title, optional shortcut, description, labelled facts, status and footer without importing game state. `features/abilities/SpellDetails.tsx` composes that layout for both action slots and spellbook; only engine snapshots supply combat numbers. Empty slots use a generic card without spell stats. New HUD help should reuse these primitives rather than importing Radix directly or duplicating spell markup. `ui/tooltip.css` owns the shared visual treatment. Human rendered review of wrapping, viewport-edge placement and hover transitions remains pending.

Tooltip regression tests cover focus/hover, Escape, accessible trigger descriptions, suppression, shared spellbook/slot details, live cooldown status and missing engine data. Local frontend checks, WASM Clippy and the complete web build passed on 2026-11-07; no rendered/browser pass is claimed. Before merge, manually review slots and spellbook near viewport edges, long/alternate bindings, loading/recharging states, locked assignments and tooltip dismissal during drag/editing.

## Stylesheet ownership

`web/src/styles/global.css` is the single CSS entry point after Radix Themes. It imports page/theme defaults and shared controls from `styles/base.css`, reusable placement and panel styles from `ui/`, and HUD styles alongside their owning features (unit frames, action bars, combat errors, diagnostics and loading). Action-slot styles also serve the spellbook and drag preview. Shared panels include dialogs, forms, bindings, tooltips, editing windows and notices.

Keep the import order explicit here rather than relying on React component import order. `styles/overrides.css` loads last for reduced-motion and narrow-viewport rules. These are ordinary global CSS selectors, not CSS Modules: splitting files organizes ownership without changing specificity or introducing dependencies. Add feature-specific rules beside that feature and register its stylesheet in the entry point; reserve shared files for genuinely shared styles. This extraction preserves existing declarations and rule order; human rendered review remains pending.

## Controls and accessibility

Defaults: WASD, Tab next target, Escape game menu, Shift+Escape clear target, 1 first slot, R practice reset, F set focus, O settings, P spellbook. Other commands initially unbound. The top-right toolbar is removed; the menu exposes all interface commands. New profiles start with assignments unlocked, without a warning banner; existing saved locks are preserved. Settings supports two entries, search/categories, clearing, defaults and explicit conflict replacement. Quick bind highlights hovered/focused slots, edits primary and has an explicit Unbind button; use Settings for secondary. Tab navigates quick-bind slots.

Ctrl/Alt/Meta/function keys and Shift+Tab are reserved; unsupported captures explain why. Escape cancels capture except when explicitly binding the menu action, where it can be assigned and Cancel exits. Shift+Tab opts out of automatic canvas focus for ordinary keyboard UI navigation. Typing, modal dialogs and exclusive editing/capture modes suspend gameplay; ordinary HUD buttons and the nonmodal spellbook do not. Tooltips/practice status explain loading, empty assignment, no target, range, occlusion, recharge and finished rounds. Rust independently validates submitted attacks.

Menu/Settings remains reachable independently of frame/bar visibility. Target and focus hide when absent during gameplay. Layout mode always previews sample frames, including hidden/absent ones. Click a frame/bar directly to edit visibility/scale/lock and selected/all resets; drag anywhere on it, without frame drag bars, dropdown selection or X/Y sliders. Drag the editor's title to move the window out of the way. Done or Escape exits. Saved scale is 60–160%, fitted smaller if needed. Minimum supported desktop viewport is 800×600. Reduced motion disables animation; rapid health/cooldown values are not live regions. Drag-only spell assignment is not keyboard-equivalent accessibility; this is an explicit requested tradeoff ([ADR 0008](decisions/0008-gameplay-first-ui.md)).

Default player/target frames sit aligned near the top left, with target to the right of player; focus sits on the right. A separately movable opponent list stacks available opponents vertically (one in the current practice ABI), independent of selection. Left-click targets; right-click focuses without changing target or opening the context menu. Set/Clear Focus buttons are removed; bindings remain available. Older saved frame positions are preserved, with the list position added automatically; use Reset all positions to adopt new defaults. Rendered placement and mouse interaction review remain pending.

## Fast iteration

### Cooldown presentation

`domain/abilities/cooldown-presentation.ts` interpolates presentation from explicit samples/timestamps. `runtime/cooldown-animation.ts` shares one requestAnimationFrame loop across every visible Pulse assignment; `features/action-bars/Cooldown.tsx` updates only the decorative sweep/label, without rerendering action slots every frame. The transparent portion grows clockwise from twelve o'clock. Ordinary quantized samples cannot reverse it; new casts, cooldown increases, resets and resumed samples can re-anchor it.

Extrapolation is capped at 150 ms when samples stall, and the visual retains a final sliver/0.1 label until Rust reports zero. The animation never changes engine state, submits an action or decides readiness. Start/end snapshots bypass HUD throttling, avoiding an extra 80 ms delay. Reduced-motion mode uses a static shaded background instead of the spiral. Rendered smoothness, direction and behavior across tab suspension still require human browser review; this is not a measured frame-rate claim.

### Commands

After `npm ci` and one complete `./scripts/build-web.sh`, use `npm run dev` for frontend hot reload without rebuilding Rust. `npm run build` builds only the frontend and copies any existing `web/public` assets to `dist`; a fresh checkout needs the complete build to play. Never publish a frontend-only build without its generated engine assets. `npm run serve` previews `dist`; `python3 -m http.server 8000 --directory dist --bind 127.0.0.1` is an alternative. Relative paths permit hosting the entire output under a subdirectory with no rewrite/router requirement.

`npm run format` writes normal multi-line formatting; `format:check`, `typecheck`, `lint`, `test` and `build` are frontend gates. `test:watch` watches both Node input and Vitest suites; `test:input` / `test:input:watch` require no npm dependencies. jsdom tests mock only browser APIs without layout implementations; they do not validate geometry, pointer-lock permissions, GPU rendering or browser compatibility. See the manual checklist in [BROWSER.md](BROWSER.md).
